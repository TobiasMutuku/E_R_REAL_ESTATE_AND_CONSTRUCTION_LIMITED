# E&R Real Estate and Construction Limited

E&R REAL ESTATE AND CONSTRUCTION LIMITED is a construction website that allows clients to interact with the contractor and view the services provided by the company.

Public marketing website for E&R Real Estate and Construction Limited.

## Local preview

Run the site through a web server; opening a `.php` file with `file://` displays source rather than executing it. With XAMPP, start Apache and MySQL in the XAMPP Control Panel, then visit:

`http://localhost/E%26R%20REAL%20ESTATE%20AND%20CONSTRUCTION%20LIMITED/quote.php`

The contact, quote, and Academy forms require the configured MySQL database. Each submission is stored for administrator follow-up; email delivery is tracked separately so a mail transport outage does not lose a lead. The Academy form posts to `academy-enquiry.php`, which includes its handler from the web-restricted `mail/` directory.

## Before production

- Configure a transactional email transport and verified sender domain before go-live. Set `ER_MAIL_FROM` to an address on that verified domain and configure PHP `mail()` to use the provider. Notifications go to the public email stored in Site settings; each new lead keeps a `sent`/`failed` delivery status and remains in MySQL if delivery fails. Legacy submissions with no known delivery outcome are marked `unknown`. Verify SPF, DKIM, DMARC, delivery logs, and bounce handling with the hosting provider.
- Public contact and quote submissions use server-side length/type checks, CSRF tokens, honeypot fields, and per-IP rate limits. Hashed rate-limit records expire after 24 hours. Keep monitoring abuse and add CAPTCHA only if the rate limiting proves insufficient.
- The `mail/` directory is denied direct web access. Only `academy-enquiry.php` is a public entry point for Academy enquiries; it includes the private handler from disk.
- The client portal remains intentionally unavailable until a separate authenticated client workspace and protected document store are implemented. The admin portal uses secure, idle-expiring sessions, role checks, CSRF-protected forms, password hashing, one-time expiring password-reset links, immediate account deactivation checks, and administrator audit events. Review Team access and the Audit log pages regularly; define an audit/event retention period that meets company and legal requirements.
- Keep source photos and video optimized for web delivery, and publish responsive image derivatives. Pages loading the shared settings script set below-the-fold images to native lazy loading and use asynchronous image decoding; keep the first carousel image eager.
- Administrator image uploads resize oversized images to a 1,920-pixel maximum dimension and WebP-compress them in the browser where supported; the server still validates the uploaded file type and size.
- Use project records for public portfolio entries. Add genuine project photos, the actual location, and a factual summary of confirmed scope and outcomes; omit unknown details rather than filling them with sample copy.
- Admin project records save as private drafts by default. Use the explicit “Save and publish” action only after confirming factual summary, verified scope and outcome, and a valid cover photo; drafts do not appear in public project listings or detail pages.
- Confirm property availability, Academy schedules and fees, credentials, and delivery commitments with the company before publishing them as current facts.
- Keep business contact details and other site-wide settings in one admin-managed source instead of copying values across individual pages.
- Project records include separate verified scope and outcome summaries. Add only evidence-backed details, location and real project photos; content review requires both scope and outcomes before publication. The admin image upload flow resizes images to a maximum 1,920-pixel dimension and converts to WebP where the browser supports it and the result is smaller. CSS keeps the image layout responsive; for high-volume production, use an image/CDN service that generates device-width `srcset` variants.
- Manage editorial articles, publication dates, categories, and moderation through the authenticated Editorial CMS. Search now operates on real published articles; comment counts, fake categories, and pagination remain removed.
- Keep database credentials in the `ER_DB_HOST`, `ER_DB_USER`, `ER_DB_PASSWORD`, and `ER_DB_NAME` environment variables on production servers. Create a dedicated MySQL account with only the required application permissions; do not use MySQL `root` in production. Local XAMPP defaults remain available for development.
- Set `ER_PUBLIC_BASE_URL` to the canonical HTTPS origin before publishing. Password recovery uses this configured origin to build links; production recovery links are never built from an untrusted Host header. `sitemap.php` uses it to emit public pages and only published project/article records; it intentionally returns HTTP 503 until the public origin is configured. `/robots.txt` excludes admin, configuration, migration, mail, and quote-upload paths from crawlers, and advertises the sitemap when the canonical origin is configured.
- The privacy information page documents the current form data flow. Have the company approve the final legal notice and define data-retention and access/deletion procedures before production.
- The root `.htaccess` disables directory listings and enables browser caching/compression when the corresponding Apache modules are enabled. Configuration and migration folders are web-inaccessible, and quote attachments are only available to authenticated administrators through the Enquiries workspace. Keep Apache overrides enabled or implement equivalent virtual-host rules.
- Keyboard focus indicators and a reduced-motion stylesheet are provided. Recheck contrast, image alternatives, and screen-reader behavior when adding or replacing page content.
- Before production changes, run `powershell -ExecutionPolicy Bypass -File scripts/backup-database.ps1`. The script writes a timestamped SQL export to the current user's `E&R Database Backups` folder, outside the web root. Store an additional encrypted copy off the web server and periodically verify a restore in a separate database; configure and test that external destination with the hosting provider's credentials.
- Configure a scheduled daily backup task on the production host (Windows Task Scheduler or the hosting provider's scheduler) to run `scripts/backup-database.ps1`; use a least-privilege backup account, secure environment-variable/secret-store access for its password, a retention window, an encrypted off-host copy, failure alerts, and regular restore tests. The repository script creates a local dump only; it does not silently configure a production scheduler or off-site destination.
- Apply `database/migrations/001_content_review_and_site_settings.sql` once before using the content review and site settings administration screens. Existing projects and properties start unpublished and must be reviewed before publication.
- Apply `database/migrations/002_editorial_cms.sql` once before creating or publishing articles in the Editorial CMS.
- Apply `database/migrations/003_enquiry_ownership_and_follow_up.sql` once to enable lead assignment and scheduled follow-up dates.
- Apply `database/migrations/004_operational_readiness.sql` once to enable verified project scope/outcomes, Academy lead storage, notification status, active accounts and last sign-in times, password-reset tokens, and the administrator audit log. The local development database was migrated during this work; apply this migration once to each other environment before deploying the updated PHP.
- Apply `database/migrations/005_notification_history_status.sql` after migration 004 to mark pre-existing email outcomes as unknown without implying they were sent or failed.
- Apply `database/migrations/006_project_media.sql` to provision the project image/video gallery table. Project listing and detail pages require the schema rather than attempting DDL during a public request.
- Apply `database/migrations/007_illustrative_property_concepts.sql` only if the company approves publishing the five explicitly illustrative property concepts. They are marked “Coming Soon,” have no advertised prices or specifications, and are not verified property inventory; replace or remove them before representing actual listings.
- Open `/admin/dashboard.php` after signing in. Use Projects, Content review, Editorial CMS, Enquiries, Site settings, Team access, and Audit log for the corresponding workflows. Roles are `admin` (all features), `content_editor` (projects/content/articles), and `enquiry_manager` (leads). Give accounts individual passwords and least-privilege roles.
- Before go-live, configure HTTPS at the web-server/load-balancer layer, force HTTP-to-HTTPS redirects there, enable secure cookies, set `ER_PUBLIC_BASE_URL`, `ER_MAIL_FROM` and the database secret in the host's protected secret store, confirm mail delivery, set upload limits, and verify that `.htaccess` overrides or equivalent virtual-host access-denial rules are active.
- Existing database tables cover admin users, projects and media, properties, contact enquiries, quote requests and attachments, articles, site settings, Academy enquiries, password resets, and audit events. Projects/properties/articles must be reviewed and published; enquiries need a human follow-up process. Plan data-retention, deletion/export, consent, account deactivation, and incident-response procedures before launch.

There is no JavaScript build step. The public pages currently load Bootstrap, jQuery, and Font Awesome from CDNs; pin and upgrade those dependencies before a long-lived production deployment.
